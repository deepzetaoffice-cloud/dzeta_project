# Plan: Deepzeta AI website v3, redesign from zero

Status: APPROVED (owner, 2026-10-17: plan approved in chat; the Figma design approved 2026-10-18; the library table amended by the owner's overrule, 2026-10-18)
Phase: v3 · Branch: `claude/redesign-v3-69988d` (cut from `docs/redesign-v3`; Phases A–D) · Decision: [0033](../decisions/0033-redesign-v3.md)

## Context

The owner rejected the live design ("Signal & Depth", decision 0008): dark navy everywhere, heavy white Montserrat, one blue accent, no imagery. It reads as amateur.

The new brief (owner, 2026-10-17):
- Redesign from zero.
- Colourful, with real images and video, animation, interactive elements, hover, parallax, scroll and 3D effects.
- An outstanding header and a detailed footer split into clear sections.
- Mobile-first, with an equally strong desktop.
- Complete technical SEO and GEO on every page: titles, descriptions, alt text, file names, video metadata.
- Designed in Figma first. The owner bought Figma Pro with a Full seat (confirmed 2026-10-17: 200 MCP calls a day).
- Keep every analytics, tag and pixel piece exactly as it is.
- Choose the stack again on GitHub + Vercel, with no leftover code or bloat.
- **Remove the 90+ performance-score rule.** Scores become information only, and no client is ever promised a score.

Facts that shape the plan:
- 15 live URLs: `/`, `/services`, 11 template service pages, `/services/custom-coded-websites` and `/privacy`.
- The site is still under the pre-launch `noindex` lock (0013), so a full rebuild carries no ranking risk.
- Copy is cleanly separated in `src/content/**`. All dark coupling lives in `src/styles/*.css` (`tokens.css` 474 lines, `effects.css` 2,322 lines), `src/lib/fx/*` and 11 components pinned with `data-theme="dark"`.
- There are no images, video, canvas or WebGL today.
- **The locked logo is dark-only.** "Deep" and the tagline are filled `#F4F6FB` (near white), so they vanish on a light background. The logo can't be edited or recoloured. The owner has white-background variants (owner items, below).

## Decisions taken in this plan (approving the plan accepts them)

1. **Framework: Next.js 16 in a fresh rebuild inside this repo.**
   - It's the best fit on Vercel, has built-in tools for metadata, sitemap, robots, images, fonts and OG images, and the tracking and schema code (React/TypeScript) carries over unchanged.
   - Astro was rejected: the site will be heavily interactive (3D, scroll scenes, demos, the agent chat), and the islands it gains would need the tracking code ported.
   - The current toolchain stays (Next 16.3.7, React 19.3, TypeScript 6.0.3, Tailwind 4.3). The old visual code is deleted, not kept alongside.
2. **Libraries added** (versions checked at install, 02 §2; amended 2026-10-18 by the owner's overrule, decision 0033 §4):

   | Package | Used for |
   |---|---|
   | `gsap` | ScrollTrigger, SplitText and MotionPath for parallax, pinning, scroll scenes and text reveals. The engine for scroll scenes. |
   | `lenis` | Smooth scroll, synced with ScrollTrigger |
   | `three`, `@react-three/fiber`, `@react-three/drei` | 3D. Loaded by dynamic import only in sections that have a 3D scene, with a poster image when motion is reduced. |
   | `@radix-ui/react-navigation-menu`, `-accordion` (and `-dialog` for dialogs other than the mobile menu) | Behaviour-only accessible primitives that we style ourselves. The mobile menu stays a native `<dialog class="dz-sheet">`, because `tracking.spec.ts` opens it. |
   | KokonutUI components (shadcn CLI, registry `@kokonutui`: `https://kokonutui.com/r/{name}.json`) and the Aceternity components named in the Figma motion spec | Copied into the repo, then restyled through the tokens: AI input, status island, backgrounds (dot field, paths, shape throw, drape), the text rotator, the card rail, the slider, beams, the text hover effect, the MacBook scroll, the compare slider. Each component's own dependencies are verified at install and named in its commit. |
   | `motion` (`motion/react`) | Arrives with the KokonutUI and Aceternity components. Used inside them only; GSAP stays the scroll-scene engine. |
   | `clsx`, `tailwind-merge` | The `cn()` helper the copied components expect |
   | `knip` (dev) | Fails CI on unused files, exports and dependencies: the guard against bloat |
   | `@next/bundle-analyzer` (dev) | Bundle report on each branch, information only |

   No icon library (the copied components use the 18 in-house UI glyphs from Figma, not `lucide-react`), no Spline runtime, no template, no CMS.
3. **Content stays in typed files in the repo** (`src/content/en/**`). Existing copy is the starting text and is re-checked against the new SEO rules page by page.
4. **Theme:** light and colourful by default. No dark mode in V1. The conflict with the performance-constraint file (it asks for dark mode as an option) is recorded in the register (C77).
5. **Performance:** measured and reported, never blocking. Removed:
   - the Lighthouse ≥ 95 gate
   - the Home 190,868 B limit
   - the font, image and JS byte caps
   - the regression rule (0020) and the Studio exemption (0031, which this makes moot)
   - `lighthouserc*.cjs`, `check-page-weight.mjs`, `measure-prod-weight.mjs`, `lhci-run.mjs` and the `@lhci/cli` dependency

   What stays are the habits that cost nothing visually: `next/image` (AVIF/WebP), lazy-loading 3D and video, and self-hosted fonts. Core Web Vitals are a small Google ranking signal.

   Copy rule added to 10: never promise a Lighthouse or PageSpeed score.

**SEO contract (new, enforced):** a typed `PageSeo` and `MediaAsset` in `src/lib/seo/`, with `check:seo` failing the build when a rule breaks (08 §7):

| Field | Rule |
|---|---|
| Title | 30–60 characters, format `{Topic} \| Deepzeta AI`, unique |
| Description | 120–160 characters, unique, answer-first |
| Page | Canonical, an OG image at 1200×630 for every page (`next/og`), exactly one H1, heading order kept, breadcrumbs plus BreadcrumbList |
| Image | `alt` required (≤ 125 characters), or an explicit `decorative: true`. Width and height required. Optional caption. File names in lowercase kebab-case and descriptive, for example `speed-to-lead-whatsapp-reply-dubai-1600w.avif`. |
| Video | Title, description, poster, WebVTT captions, transcript, duration and upload date, emitted as VideoObject plus a video sitemap entry |
| Site | `sitemap.ts` with image and video entries (it doesn't exist today), `llms.txt`, hreflang-ready for Arabic later |

Character counts are common practice; Google truncates by pixel width, not characters.

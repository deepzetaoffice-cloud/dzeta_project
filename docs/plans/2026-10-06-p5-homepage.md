## The JavaScript budget (07 §2, 13 §7, decision 0021)

- **First load today:** 11,077 B of our own JS (cap 11,264 B) — **187 B headroom**. The plan's rule: **no new first-load modules**. All P5 interactivity (FAQ chips/copy-link/deep links, story replay, the LCP stamp, demo panels) is delivered by lazy modules that load on first pointer/focus/in-view, through one shared loader (`lazy.ts`, target ≤ 0.2 KB of first-load wiring) and the already-lazy click path (`clicks.ts`).
- **Each lazy module is measured** per 13 §7's method (minified, sibling imports external, gzip 6) against its cap in the effect register, and the measurement is reported.
- **`OWN_JS_HOME` is raised by the measured first-load delta only** (expected ≈ 0–200 B; the loader wiring). If the measured delta doesn't fit under 11,264 B, work stops and the owner decides (a cap change is a new decision, 0021 precedent) — nothing is silently slimmed or absorbed.

## Risks & mitigations

- **Page weight (top risk):** ≈ 16.8 KB of room for all new HTML + CSS + first-load JS across 11 sections, 8 FAQ `<details>` and the story SVGs. Mitigation: SVG/CSS-only visuals, no raster images, simple geometry, copy compresses ~4:1; measured at S4/S5/S7, not only at the end. Breach → stop (07 §5); the owner's exception path is decision 0020.
- **The 187 B of JS headroom:** the lazy-loader strategy targets ≈ 0; if the wiring measures over, the fallback is moving the wiring fully into the already-lazy click path (accepting that a keyboard-only visitor's very first chip activation loads-then-requires-a-second-press, announced honestly) — or the owner decides. Never a silent cap change.
- **European Home's lab LCP (2,550 ms allowance, C61):** the hero gains the proof card and story-chat markup in the first viewport. Mitigation: the H1 stays the LCP element, visible and unanimated at first paint (13 §3 rule 2); story-chat is a delayed one-shot that plays after LCP; the proof card is small. Both profiles measured at S4; a median over 2,550 ms stops work.
- **CLS from late-playing stories and the pinned scene:** reserved space (aspect-ratio boxes, min-heights) for every story frame; the pinned scene's steps are in normal flow (07 §3).
- **The FAQ module was never validated in the Design Lab** (its spec status is LAB): it is validated in the build — keyboard and screen-reader semantics come from native `<details>`, plus the e2e set (axe, chips, no-JS, deep links, both themes, Reduce effects). Flagged to the owner (open question 2).
- **Parity drift between the visible FAQ and the FAQPage block:** one source (`faq-bank.ts`) feeds both; the extended `check:schema` asserts the Q&A text appears in the rendered page; the golden fixture pins the bytes.
- **Icon tier deviation:** home.md asks for "Tier 2 step icons" in §07, but the Tier 2 type is contract-bound to exact catalogue names (C36's registry; `icons.test.ts` pins it) — Audit/Build/Launch/Improve are process steps, not catalogue services. Recommended: Tier 1 (open question 1).
- **The other session shares this checkout** (lesson 8): `git diff` on every shared file before staging; every `git add` names its files; the other session's unstaged files (`.env.example`, `Planning Folder/**`, `docs/design/app-demo.md`, `docs/plans/2026-09-29-design-direction-v2.md`, `docs/owner/myself/**`, the OG prototype PNGs, the GTM JSONs and handoff) are never staged.
- **`git push` can exit 0 without updating the remote** (three times on 2026-10-05/06): every push is verified with `git ls-remote origin feat/homepage`; push again if the ref didn't move.
- **Post-outage Actions runner noise:** a single one-off lhci assertion failure on an otherwise-clean run is rerun once; twice the same way is real and reported.
- **Local gates:** vitest can't collect locally (machine issue) — logic validated via `.scratch/` Node-TS-loader scripts, deleted before finishing; the dev server on port 3000 blocks local Playwright/lhci — those gates run in CI, which is the evidence of record.
